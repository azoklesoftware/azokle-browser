## 🛡️ Browser Permissions Architecture, Async Clipboard & Popup Crash Remediation

### 1. Popup Crash Elimination & Unopened GeckoSession Contract (`TabManager.kt` & `AzokleNavigationDelegate.kt`)
- **Resolved Fatal AssertionError**: Resolved `java.lang.AssertionError: Must use an unopened GeckoSession instance` encountered when web applications triggered `window.open` or delayed popup modals.
- **Root Cause Analysis**:
  - `GeckoPromptDelegateImpl.onPopupPrompt` invoked `onPopupRequested?.invoke(targetUri)` which called `BrowserScreen.onNewWindowRequested()`, triggering a redundant tab creation concurrently with `AzokleNavigationDelegate.onNewSession()`.
  - In `TabManager.openTabFromParent()`, `selectTab(newTab.id)` was called synchronously. This immediately mutated `activeTabId`, prompting Jetpack Compose to eagerly instantiate `GeckoBrowserView` and call `session.open(runtime)`. When GeckoView internally returned from `onNewSession`, the session was already open, violating GeckoView's internal assertion contract.
- **Sovereign Architectural Resolution**:
  - Removed duplicate tab creation from `GeckoPromptDelegateImpl.onPopupPrompt`.
  - Added `selectAfterOpen: Boolean = true` parameter to `TabManager.openTabFromParent()` (defaulting to `false` for parent-spawned sessions).
  - Deferred tab selection to the MainLooper queue in `AzokleNavigationDelegate.onNewSession()`, returning the unopened session to GeckoView first so GeckoView's internal peer binding completes cleanly before Compose attaches.

### 2. Standard-Compliant Async Clipboard Pipeline (`AzokleSelectionDelegate.kt` & `GeckoConfigManager.kt`)
- **Clipboard Read/Write Access Unlocked**: Eliminated hard-coded `AllowOrDeny.DENY` stub in `AzokleSelectionDelegate.onShowClipboardPermissionRequest`.
- **Granular Prompting & Persistence**: Integrated `SitePermissionsManager` and `SitePermissionType.CLIPBOARD` with `SitePermissionPromptSheet`, giving users one-tap control to allow or deny clipboard access per site.
- **Zero-Delay Async Clipboard Injection**: Injected `dom.events.asyncClipboard.readText: true`, `dom.events.asyncClipboard.clipboardItem: true`, and `dom.events.asyncClipboard.dataTransfer: true` into `geckoview-config.yaml`, eliminating delayed `writeText` stalls and unblocking `navigator.clipboard.readText()`.

### 3. Android OS Runtime Permissions Bridge (`AzoklePermissionDelegate.kt` & `MainActivity.kt`)
- **Runtime Permission Forwarding**: Overrode `onAndroidPermissionsRequest` in `AzoklePermissionDelegate`, replacing GeckoView's default `callback.reject()` bytecode fallback with a bridge to `MainActivity.requestAndroidPermissions()`.
- **FIFO Request Queue**: Built an activity-level permission request queue in `MainActivity` with `ActivityResultContracts.RequestMultiplePermissions()`, ensuring concurrent OS permission prompts resolve deterministically without dropping callbacks.
- **Atomic Callback Gating Fix (`SitePermissionRequest.kt`)**: Gated `isResolved.compareAndSet(false, true)` inside `grantMedia()`, `grantContent()`, and `grantClipboard()` to only trigger when the respective callback is non-null, preventing media grant checks from swallowing content permission resolutions (Geolocation, Notifications).
- **Approximate Location Tolerance (Android 12+)**: Updated `SitePermissionType.kt` and `BrowserScreen.kt` to accept `ACCESS_COARSE_LOCATION` without demanding fine location when users choose approximate location in Android's system dialog.

### 4. Screen Share Media Source Routing (`AzoklePermissionDelegate.kt`)
- **Decoupled Screen Capture from Camera Hardware**: Resolved issue where `getDisplayMedia` screen share requests were routed to `SitePermissionType.CAMERA`, prompting for hardware `CAMERA` permissions.

### 5. WebXR & WebAuthn Engine Capabilities
- **WebXR (VR / AR)**: Mapped `PERMISSION_XR` to `SitePermissionType.VR_AR` and activated `dom.vr.enabled: true` and `dom.vr.webxr.enabled: true`.
- **WebAuthn / Passkeys**: Enabled `security.webauth.webauthn: true`, integrating FIDO2 / Passkey authentication via Android Credential Manager.

### 6. GeckoView Engine Standards vs Chromium-Only Proprietary APIs Matrix
- **Security-First Architecture**: Documented and verified API boundaries between W3C standards supported by GeckoView and proprietary Chromium APIs:
  - **Supported in Azokle / GeckoView**: Geolocation (Precise & Approximate), Notifications, Camera & Microphone, Screen Share, Async Clipboard (Read & Write), Device Orientation & Motion, Popups & Delayed Popups, WebXR, WebAuthn.
