### 5. Tab Group Security, Privacy Isolation & Ghost Pruning Hardening

  - Fixed dual-source-of-truth desynchronization by atomically removing moved tabs from previous groups and pruning empty ghost groups in `createGroup()` and `addTabToGroup()`.

- **Undo Support for Group Closures**:
  - `closeGroup()` now records non-private tabs into the thread-safe `_recentlyClosed` deque, enabling 1-tap undo for accidental tab group closures.

  - Integrated `LaunchedEffect(tabs.isEmpty())` auto-dismissal to prevent frozen dialogs when the last tab of a group is closed.

### 15. History Subsystem Deep Audit, Security, Persistence & UI/UX Overhaul
- **Persistent Storage Deletion Desynchronization Bug Fixed**:
  - Resolved a critical desynchronization flaw where deleting items via in-memory Rust IDs (`hist_...`) failed to match auto-incrementing integer IDs in SQLite (`COL_ID`), causing deleted history items to persist and reappear upon app restart.
  - Added URL-aware atomic deletion (`deletePlaceByUrl` & `deletePlacesByUrls`) ensuring synchrony between Rust and SQLite storage tiers.
- **Eliminated Title-Update Visit-Doubling Bug**:
  - Fixed an integrity bug where document title updates from GeckoView parsed events triggered `record_visit_internal` in Rust, falsely incrementing `visit_count` and mutating timestamps.
  - Implemented dedicated `update_title` in Rust (`crates/services/history`), exposed via JNI (`historyUpdateTitle`), and integrated in `HistoryManager.updateTitle`.
- **SQLite Concurrency, FTS4 & Forensic Security Hardening**:
  - Wrapped `recordPlaceVisit`, `clearTimeRange`, and `deletePlacesByUrls` in explicit SQLite transactions (`beginTransaction()`, `setTransactionSuccessful()`, `endTransaction()`).
  - Activated indexed FTS4 `MATCH` query execution in `searchFts` with graceful fallback to `LIKE`.
  - Added comprehensive table purge in `clearAllSecurely()`, wiping `TABLE_PLACES_FTS` alongside places, visits, downloads, and session metadata.
- **Ergonomic UI/UX Modernization & Focus Ring Elimination**:
  - Removed focus-ring / halo artifacts across all header buttons, filter chips, search clear icons, and item action controls (`indication = null` with explicit `MutableInteractionSource`).
  - Added Material 3 item action dropdowns with options to Open, Open in New Tab, Open in Private Tab, Copy Link, Share Link, Select Multiple, and Delete Entry.
  - Added "Select All" / "Deselect All" capabilities in multi-selection mode with batch deletion.
  - Implemented 5-tier date grouping (Today, Yesterday, Previous 7 Days, Last 30 Days, Older) computed asynchronously off the UI thread via `Dispatchers.Default`.
  - Debounced search query typing to maintain 60fps scrolling and eliminate UI frame drops.
- **Comprehensive Test Suite**:
  - Expanded unit test coverage (`HistoryItemTest.kt` and Rust `azokle-history` tests) verifying host parsing, visit count preservation on title updates, date grouping buckets, and search filter partitioning.

### 16. Web Navigation Crash Elimination & History Purge Persistence Guarantee
- **UnsatisfiedLinkError Website Navigation Crash Resolved**:
  - Recompiled multi-architecture release native binaries (`arm64-v8a`, `armeabi-v7a`, `x86_64`) containing the newly exported `Java_com_azokle_search_core_AzokleCore_historyUpdateTitle` symbol using `cargo ndk`.
  - Hardened JNI entry points in `AzokleCore.kt` and `HistoryManager.kt` by catching `Throwable` (rather than just `Exception`), ensuring that any runtime linkage discrepancy degrades gracefully without triggering an uncaught `Error` crash.
- **Root-Cause Resolution of History Persistence on Clear**:
  - **SQLite Transaction Rollback Fix**: Removed direct `DELETE FROM TABLE_PLACES_FTS` within `clearAllSecurely()`. Because `TABLE_PLACES_FTS` is an external-content virtual table (`content='azokle_places'`), direct deletion threw an SQLiteException that silently caused Android SQLite transactions to roll back all deletions in `TABLE_PLACES` and `TABLE_VISITS`. Added dedicated `clearAllHistory()` and updated `clearTimeRange()`.
  - **Coroutine Self-Cancellation Fix**: Replaced parent supervisor job cancellation in `clearAllSync()` with targeted debounced `saveJob?.cancel()` and guarded execution within `withContext(NonCancellable)` so history clearing is never aborted midway.
  - **Cold-Start Re-import Guard**: Updated `saveToDisk()` to unconditionally purge the on-disk JSON cache (`azokle_browser_history.json`) when history is empty, preventing `loadHistory()` from re-importing purged entries on next cold start.
  - **Settings Integration**: Unified "Clear Browsing & Search History" in `SettingsScreen.kt` to trigger both `prefsManager.clearRecentSearches()` and `HistoryManager.clearAll()`.
