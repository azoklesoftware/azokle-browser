# Azokle Android Release v2.1.0 Changelog

## 🛡️ Enterprise Security Hardening, Zero-Leak Tor Isolation, Credential Protection & CA Defense

---

### 1. Digital Trust Incident Defense & CA Revocation Hardening
- **CRLite & PKIX Certificate Pinning**:
  - Configured GeckoView Quantum engine preferences to strictly mitigate compromised or rogue intermediate Certificate Authority (CA) attacks (e.g. eMudhra / emSign security incidents):
    - `security.pki.crlite_mode: 2` (Enforces full CRLite certificate revocation list verification)
    - `security.cert_pinning.enforcement_level: 2` (Strict static key pinning enforcement across critical domains)
    - `security.OCSP.enabled: 1` (Online Certificate Status Protocol checking)
  - Hardened `network_security_config.xml` to enforce TLS-only communications (`cleartextTrafficPermitted="false"`) with system-level trust anchors.

---

### 2. Comprehensive Tor Mode & Privacy Isolation Hardening
- **AZK-VULN-01: Hardware Sensor & Geolocation Isolation**:
  - Hard-blocked Geolocation and VR/AR sensors in Tor browsing sessions to prevent physical coordinate leakage and hardware deanonymization.
- **AZK-VULN-07: Media Hardware & Peripheral Fingerprinting Shield**:
  - Enforced unconditional rejection of Camera, Microphone, and Screen-sharing requests in Tor mode to prevent peripheral enumeration and acoustic/visual device fingerprinting.
- **AZK-VULN-12: Ad Attribution & Beacon Protection**:
  - Prevented conversion beacons (`bat.bing.com`, `googleadservices.com`) and attribution tracker exemptions from executing in Private and Tor tabs in `AdClickManager.kt` and `BrowserScreen.kt`.
- **AZK-VULN-14: In-App Update Checker Tor Routing**:
  - Routed background GitHub update checks in `AppUpdateChecker.kt` through local SOCKS5 proxy (`127.0.0.1:socksPort`) when Tor is active, eliminating clearnet IP leaks during version checks.
- **AZK-VULN-15: DoH & CNAME Uncloaking Clearnet Leak Prevention**:
  - In `DnsOverHttpsManager.kt`, disabled direct CNAME uncloaking during Tor mode and routed shared DNS lookups through `TorRemoteDns` (`0.0.0.0`), forcing SOCKS5 remote proxy command `0x03` DNS resolution.
- **AZK-VULN-16: Omnibar Autosuggestion Suppression**:
  - Suppressed search autosuggestion HTTP queries when typing in Tor or Private tabs in `BrowserUrlEditSheet.kt` and `SearchRepository.kt`.
- **AZK-VULN-18: RFC 7686 & W3C Secure Context Alignment for Tor Onion Services**:
  - Recognized `.onion` Hidden Services under Tor as trustworthy origins in `AzoklePermissionDelegate.kt` and `PwaInstallabilityValidator.kt`, ensuring proper handling without compromising hardware isolation.

---

### 3. Navigation Security & Intent Sanitization
- **AZK-VULN-11: Direct Scheme Navigation Bypass & UXSS Mitigation**:
  - Gated URL navigation and QR code scanner dispatching in `BrowserScreen.kt` with `NavigationSecurity.isForbiddenWebScheme()`.
  - Added `"javascript"` to the forbidden schemes set to block self-XSS, omnibox script execution, and bookmarklet UXSS vulnerabilities.
- **AZK-BUG-07 / H-3: Intent Injection & Self-Targeting Defense**:
  - Enforced strict intent sanitization across external navigation handlers, preventing untrusted web content from self-targeting internal browser components or launching unprompted system activities.

---

### 4. Credential Vault Isolation & FileProvider Hardening
- **AZK-VULN-17: Least-Privilege Credential Storage Delegate**:
  - Hardened `AzokleAutocompleteStorageDelegate.kt` by having zero-argument `onLoginFetch()` return an empty array, preventing bulk ingestion of all decrypted passwords into GeckoView engine memory.
  - Retained strict origin-scoped credential fetching via `onLoginFetch(domain)` governed by `OriginMatcher.kt`.
- **AZK-BUG-08: Sandboxed Download FileProvider Resolution**:
  - Added `<files-path name="private_downloads" path="downloads_private/" />` and corrected `<cache-path name="app_staging" path="download_staging/" />` in `file_paths.xml`, fixing `IllegalArgumentException` when opening or sharing sandboxed Private/Tor downloads.
- **AZK-VULN-13: Backup & Data Extraction Exclusions**:
  - Updated `data_extraction_rules.xml` and `backup_rules.xml` to explicitly exclude `context.filesDir` and external storage paths, preventing session and tab state leakage via cloud or device-to-device transfers.
