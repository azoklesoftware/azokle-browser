# Azokle Android Release v2.1.0 Changelog

## 🛡️ Enterprise Security Hardening, Zero-Leak Tor Isolation, Credential Protection & CA Defense

---

### 1. Digital Trust Incident Defense & CA Revocation Hardening
- **CRLite & PKIX Certificate Pinning**:
  - Configured GeckoView Quantum engine preferences to strictly mitigate compromised or rogue intermediate Certificate Authority (CA) attacks (e.g. eMudhra / emSign security incidents):
    - `security.pki.crlite_mode: 2` (Enforces full CRLite certificate revocation list verification)
    - `security.cert_pinning.enforcement_level: 2` (Strict static key pinning enforcement across critical domains)
    - `security.OCSP.enabled: 1` (Online Certificate Status Protocol checking)
  - Hardened `network_security_config.xml` to enforce TLS-only communications (`cleartextTrafficPermitted="false"`) with system-level trust anchors.

---

### 2. Comprehensive Tor Mode & Privacy Isolation Hardening
- **AZK-VULN-01: Hardware Sensor & Geolocation Isolation**:
  - Hard-blocked Geolocation and VR/AR sensors in Tor browsing sessions to prevent physical coordinate leakage and hardware deanonymization.
- **AZK-VULN-07: Media Hardware & Peripheral Fingerprinting Shield**:
  - Enforced unconditional rejection of Camera, Microphone, and Screen-sharing requests in Tor mode to prevent peripheral enumeration and acoustic/visual device fingerprinting.
- **AZK-VULN-12: Ad Attribution & Beacon Protection**:
  - Prevented conversion beacons (`bat.bing.com`, `googleadservices.com`) and attribution tracker exemptions from executing in Private and Tor tabs in `AdClickManager.kt` and `BrowserScreen.kt`.
- **AZK-VULN-14: In-App Update Checker Tor Routing**:
  - Routed background GitHub update checks in `AppUpdateChecker.kt` through local SOCKS5 proxy (`127.0.0.1:socksPort`) when Tor is active, eliminating clearnet IP leaks during version checks.
- **AZK-VULN-15: DoH & CNAME Uncloaking Clearnet Leak Prevention**:
  - In `DnsOverHttpsManager.kt`, disabled direct CNAME uncloaking during Tor mode and routed shared DNS lookups through `TorRemoteDns` (`0.0.0.0`), forcing SOCKS5 remote proxy command `0x03` DNS resolution.
- **AZK-VULN-16: Omnibar Autosuggestion Suppression**:
  - Suppressed search autosuggestion HTTP queries when typing in Tor or Private tabs in `BrowserUrlEditSheet.kt` and `SearchRepository.kt`.
- **AZK-VULN-18: RFC 7686 & W3C Secure Context Alignment for Tor Onion Services**:
  - Recognized `.onion` Hidden Services under Tor as trustworthy origins in `AzoklePermissionDelegate.kt` and `PwaInstallabilityValidator.kt`, ensuring proper handling without compromising hardware isolation.

---

### 3. Navigation Security & Intent Sanitization
- **AZK-VULN-11: Direct Scheme Navigation Bypass & UXSS Mitigation**:
  - Gated URL navigation and QR code scanner dispatching in `BrowserScreen.kt` with `NavigationSecurity.isForbiddenWebScheme()`.
  - Added `"javascript"` to the forbidden schemes set to block self-XSS, omnibox script execution, and bookmarklet UXSS vulnerabilities.
- **AZK-BUG-07 / H-3: Intent Injection & Self-Targeting Defense**:
  - Enforced strict intent sanitization across external navigation handlers, preventing untrusted web content from self-targeting internal browser components or launching unprompted system activities.

---

### 4. Credential Vault Isolation & FileProvider Hardening
- **AZK-VULN-17: Least-Privilege Credential Storage Delegate**:
  - Hardened `AzokleAutocompleteStorageDelegate.kt` by having zero-argument `onLoginFetch()` return an empty array, preventing bulk ingestion of all decrypted passwords into GeckoView engine memory.
  - Retained strict origin-scoped credential fetching via `onLoginFetch(domain)` governed by `OriginMatcher.kt`.
- **AZK-BUG-08: Sandboxed Download FileProvider Resolution**:
  - Added `<files-path name="private_downloads" path="downloads_private/" />` and corrected `<cache-path name="app_staging" path="download_staging/" />` in `file_paths.xml`, fixing `IllegalArgumentException` when opening or sharing sandboxed Private/Tor downloads.
- **AZK-VULN-13: Backup & Data Extraction Exclusions**:
  - Updated `data_extraction_rules.xml` and `backup_rules.xml` to explicitly exclude `context.filesDir` and external storage paths, preventing session and tab state leakage via cloud or device-to-device transfers.

### 5. Advanced Adversarial Security Remediation & Cryptographic Hardening (AZK-VULN-13 – AZK-VULN-22)
- **AZK-VULN-13: OAuth Callback Spoofing & Zero-Click App Intent Launches**:
  - In `OAuthRedirectHandler.kt`, blacklisted non-OAuth application schemes (`slack`, `whatsapp`, `tg`, `telegram`, `viber`, `skype`, `zoommtg`, `fb`, `twitter`, `instagram`, `snapchat`, `tiktok`, `tel`, `sms`, `mailto`, `market`, `upi`, `paytmmp`, etc.) from being classified as gesture-exempt OAuth callbacks.
  - Enforced RFC 8252 requirement: custom schemes must either follow reverse-DNS convention (`com.example.app:`) or point to dedicated authentication callback endpoints (`/oauth2callback`, `/callback`, `/redirect`).
- **AZK-VULN-14: Plaintext Password Vault Clipboard Leaks**:
  - In `PasswordManagerScreen.kt`, removed plaintext JSON password vault dumping to the Android system clipboard.
  - Implemented direct file export via Android's Storage Access Framework (`ActivityResultContracts.CreateDocument("application/json")`), streaming decrypted credentials directly into an isolated, user-selected output stream with zero clipboard footprint.
- **AZK-VULN-15: Cross-Origin WebAuthn Assertion Signature Forging**:
  - In `crates/crypto/src/passkey.rs` and `crates/crypto/src/lib.rs`, enforced W3C WebAuthn Level 3 specification in `SovereignPasskey::sign_assertion`: requires `authenticator_data.len() >= 37` and strictly validates `authenticator_data[..32] == Sha256::digest(rp_id)`.
  - Zeroized temporary signature buffers and exposed `clear_global_passkey_vault()` for in-memory purge.
- **AZK-VULN-16: Incineration Engine Passkey & PWA Residual Footprint**:
  - In `DataBurnEngine.kt`, wired Layer 12 to purge in-memory PWA tab states (`PwaManager.clear()`), encrypted shared preferences passkey metadata (`PasskeyVaultManager.clearAll()`), and native Rust passkey stores (`AzokleCore.passkeyClearVault()`).
  - Exposed `azokle_passkey_clear_vault` across C-ABI (`bindings/c`) and JNI (`bindings/kotlin`).
- **AZK-VULN-17: Coil Image Loader SSRF & Tor Clearnet DNS Leaks**:
  - In `AzokleApplication.kt`, configured Coil singleton `ImageLoader` with `DownloadManager.ClearnetSafeDns`.
  - In `DownloadManager.kt`, hardened `ClearnetSafeDns` to fail closed against `.onion` domains over clearnet DNS.
  - In `MediaPlaybackManager.kt`, aborted remote artwork fetching during private sessions and validated all URLs with `ReaderExtractor.isSafePublicUrl`.
  - In `GeckoEngineManager.kt`, `ReaderExtractor.kt`, and `ReaderModeScreen.kt`, validated extracted article lead image URLs (`og:image`) against private/internal subnets and cloud metadata before rendering.
- **AZK-VULN-18: WebRTC & Widevine DRM Hardware Deanonymization in Tor**:
  - In `GeckoConfigManager.kt`, disabled Widevine EME (`media.eme.enabled: false`, `media.eme.widevine.enabled: false`) when Tor mode is active to prevent device-unique hardware/keystore DRM certificates from deanonymizing users.
  - Completely disabled WebRTC (`media.peerconnection.enabled: false`, `media.peerconnection.use_document_iceservers: false`) during Tor sessions to eliminate ICE candidates and local IP leaks.
- **AZK-VULN-19: Tor Isolation Bypass in PWA External Navigation**:
  - In `PwaActivity.kt`, passed `isPrivate = isTor, isTor = isTor` into `ExternalNavigationHandler.handleNavigation`, enforcing Tor circuit protection and user confirmation before external intent dispatches.
- **AZK-VULN-20: Private Media Playback Lockscreen Notification Leaks**:
  - In `MediaPlaybackService.kt`, masked notification title to `"Private Media Playing"`, set subtitle to `"Azokle Browser"`, omitted artwork bitmaps, and set `NotificationCompat.VISIBILITY_SECRET` whenever `isPrivateSession` is true.
- **AZK-VULN-21: Dangerous URI Schemes & Path Traversal in Download Service**:
  - In `crates/services/downloads/src/lib.rs`, implemented `is_safe_download_url`, blocking `javascript:`, `file:`, `intent:`, `content:`, `about:`, `chrome:`, `resource:`, and control characters.
  - Sanitized destination paths against directory traversal (`../`, `..\`, null bytes) in `create_download` and `import_json`.
- **AZK-VULN-22: Tab URL Injection & Title Control Injections in Tabs Service**:
  - In `crates/services/tabs/src/lib.rs`, implemented `TabSession::sanitize_tab_url`, redirecting dangerous execution schemes (`javascript:`, `file:`, `chrome:`, `resource:`, `jar:`, `view-source:`) to the safe homepage.
  - Stripped CRLF injections from tab titles during construction and updates.

### 6. Deep Security Remediation & Vault Origin Isolation (AZK-VULN-23 – AZK-VULN-30)
- **AZK-VULN-23: Cross-Port Credential Leakage & Autofill Port Truncation (CWE-346 / CWE-522)**:
  - In `PasswordVaultManager.kt` and `GeckoPromptDelegateImpl.kt`, enforced canonical origin resolution (`OriginMatcher.toCanonicalOrigin(raw)`), preserving schemes, hosts, and non-default ports (`scheme://host[:port]`).
  - Completely isolated custom port services (e.g. `https://example.com:8443` vs `https://example.com:443`), preventing privilege escalation, cross-service credential leakage, and origin confusion.
- **AZK-VULN-24: Incomplete In-Memory Credential Scrubbing on Incineration (CWE-459 / CWE-212)**:
  - In `DataBurnEngine.kt`, wired `PasswordVaultManager.clearAllLogins()` into Layer 12 volatile storage & memory purge, ensuring zero credential persistence across panic wipes and session burns.
- **AZK-VULN-25: Unverified Dynamic Adblock Filter Execution (CWE-494 / CWE-353)**:
  - In `FilterUpdateManager.kt`, enforced fail-closed signature verification on dynamic OTA filter lists (`loadFilterContent`). Rejects any unverified dynamic filter update lacking an authentic `.sig` signature and falls back safely to bundled local asset rules.
- **AZK-VULN-26: Persistent Bookmark XSS & Arbitrary Internal Navigation (CWE-79 / CWE-20)**:
  - In `EncryptedVaultManager.kt` and `crates/services/bookmarks/src/lib.rs`, implemented URL sanitization filtering control characters, non-ASCII whitespace, BOM (`\uFEFF`), zero-width space (`\u200B`), and non-breaking spaces.
  - Restricted internal schemes strictly to `about:blank` and `about:tor`, completely blocking dangerous internal debug/config engines (`about:config`, `about:debugging`).
  - Enforced title sanitization in `addBookmark`, `toggleBookmark`, `updateBookmark`, `addQuickLink`, and JSON imports/exports, stripping ASCII/Unicode control characters and capping lengths to 256 characters.
- **AZK-VULN-27: Userinfo Authority Spoofing & Tor SOCKS5 Leakage (CWE-20 / CWE-601)**:
  - In `crates/tor/src/lib.rs`, `DownloadManager.kt`, and `ReaderExtractor.kt`, hardened authority host parsing against embedded userinfo (e.g. `http://user:pass@legitimate.onion:80/` and `http://malicious.com:pwd@target.onion:80/`).
  - Stripped authority credentials before port and host resolution (`authority.substringAfterLast('@')`), preventing attacker-controlled clearnet redirects, SSRF bypasses, and DNS leakage.
- **AZK-VULN-28: In-Memory Credential Leakage into Autocomplete Storage (CWE-200 / CWE-522)**:
  - In `AzokleAutocompleteStorageDelegate.kt`, bound login storage events to tab session contexts (`TabManager.activeTabId`), strictly dropping credential persistence during Private and Tor browsing sessions.
  - Normalized origins via `OriginMatcher.toCanonicalOrigin` and implemented strict exact-origin matching before falling back to domain matching during credential prompts.
- **AZK-VULN-29: Unbounded History Records & Control Character Injection (CWE-400 / CWE-20)**:
  - In `crates/services/history/src/lib.rs`, enforced URL length boundaries (<= 4096 bytes) and sanitized URLs and titles against control characters, CRLF, and oversized inputs (<= 256 characters) in `record_visit_internal` and `update_title`.
- **AZK-VULN-30: Truncated or Null WebAuthn ClientDataHash Injection (CWE-345 / CWE-327)**:
  - In `crates/crypto/src/passkey.rs`, enforced strict W3C WebAuthn Level 3 compliance in `SovereignPasskey::sign_assertion` requiring `client_data_hash.len() == 32`, rejecting arbitrary length, null, or truncated client data hashes.
