# Azokle Android Release v2.0.2 Changelog

## 🛡️ Production Crash Elimination & Native ANR Resolution

---

### 1. 🧅 Tor Daemon JNI `NoSuchFieldError` Elimination (`proguard-rules.pro`)
- **Resolved Fatal JNI Reflection Crash**: Fixed `java.lang.NoSuchFieldError` in `org.torproject.jni.TorService.mainConfigurationFree`.
- **R8 Proguard Rules Hardening**:
  - Identified that R8 release shrinking stripped and obfuscated private/internal C-struct pointers and configuration fields accessed by `libtor.so` via `GetFieldID`.
  - Added full preservation rules for `org.torproject.**`, `info.guardianproject.**`, and `com.msopentech.thali.toronionproxy.**`, ensuring all native JNI method bindings and data structures remain intact in release builds.

---

### 2. ⚡ GeckoView Native Lock Contention & ANR Resolution (`AzokleApplication.kt`)
- **Resolved Input Dispatching Timed Out ANR**: Fixed `mozilla::detail::ConditionVariableImpl::wait_for` native mutex lock contention on the Main UI Thread.
- **Main-Thread Bound Initialization**:
  - Eliminated the detached background thread in `AzokleApplication.onCreate()` that was concurrently instantiating `GeckoRuntime` while `MainActivity` and `GeckoView` were binding sessions on the UI thread.
  - Aligned `GeckoRuntime` instantiation with the Android Main Looper, allowing Gecko's internal multi-threaded engine (`GeckoMain`, `Compositor`, `GPU`) to coordinate native condition variables without deadlocking UI input dispatching.

---

### 3. 🔒 Complete GeckoView JNI Precision Protection
- Hardened `proguard-rules.pro` to keep all classes, methods, and member variables across `org.mozilla.geckoview.**` and `org.mozilla.gecko.**`, preventing native-to-Java callback failures and condition variable stalls.

---

### 4. 📦 Verification
- **Unit & Regression Suite**: `./gradlew testDebugUnitTest` passed with 0 errors.
